# Skill Anatomy

Each skill should be a compact workflow, not a long essay.

## Required Shape

```markdown
---
name: skill-name
description: What this skill does and when to use it.
---

# Skill Name

## When To Use

## Process

## Verification

## Stop Conditions
```

## Guidelines

- Put the trigger and outcome in `description`.
- Keep `SKILL.md` focused on the workflow.
- Move long checklists, examples, and templates into `references/` or skill-local resources.
- End with evidence requirements, not vibes.
- Prefer one clear workflow over many optional branches.
